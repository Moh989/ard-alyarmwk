# النسخ الاحتياطي والاستعادة

أضيفت أداتان تعملان من سطر الأوامر، واختُبرت الاستعادة إلى قاعدة MySQL عشوائية معزولة. تشمل النسخة جميع جداول الموقع، بما فيها حسابات المسؤولين وتجزئات كلمات المرور ورسائل التواصل، وجميع ملفات الوسائط المسجلة. لا تشمل أسرار `config/local.php` أو كود الإصدار؛ احتفظ بهما بصورة منفصلة وآمنة.

```sh
php bin/backup.php
```

يطبع مسار أرشيف جديد داخل `storage/backups/` بصلاحيات خاصة 600. تُقرأ الجداول ضمن معاملة متسقة، وتُفحص بصمات الملفات بعد إغلاق الأرشيف. لا تُحذف النسخ القديمة آلياً. هذه الأرشيفات تحتوي بيانات خاصة؛ لا تضعها في `public/` أو ترسلها مع حزمة المصدر. اطلب من مسؤول الاستضافة جدولة النسخ وتخزين نسخة خارج الخادم وتحديد مدة الاحتفاظ والحذف وفق سياسة الشركة. حذف رسالة من لوحة الإدارة لا يزيلها من نسخ سابقة، ويجب أن تشمل معالجة طلبات الحذف دورة الاحتفاظ بالنسخ أيضاً.

## الاستعادة

1. جهّز نسخة مطابقة من الكود وأسرار الإعداد على بيئة خاصة.
2. أنشئ **قاعدة جديدة فارغة**، واضبط إعدادها في ملف خاص خارج الويب. الأداة ترفض قاعدة تحتوي سجلات؛ لا تحذف القاعدة الحية.
3. مرّر ملف الإعداد بمتغير `ARD_CONFIG`:

```sh
ARD_CONFIG=/private/recovery.php php bin/migrate.php
ARD_CONFIG=/private/recovery.php php bin/restore.php /private/backup.zip --confirm-database=RECOVERY_DATABASE
```

لا تشغل `seed.php` على قاعدة الاستعادة. تستعيد الأداة السجلات والوسائط، وتتحقق من المخطط وبصمات الملفات. ترفض استبدال ملف موجود بمحتوى مختلف؛ استخدم مجلد إصدار نظيفاً عند استعادة إصدار أقدم. بعد الاستعادة افحص الصفحة الرئيسية واللغتين وتسجيل الدخول والرسائل والوسائط والنسخة الخفيفة للملف. لا تحوّل الموقع إلى قاعدة الاستعادة إلا بعد نجاح المراجعة.

الاختبار المنفذ `php tests/backup-restore.php`: حفظ واستعادة رسالة اختبار وحساب إداري وملف مرفوع ومحتوى الموقع، ثم رفض الاستعادة فوق بيانات موجودة أو إلى اسم قاعدة غير مطابق. جميع بيانات الاختبار وقواعده وأرشيفاته أزيلت بعد الاختبار. لم تُجرّب استعادة على استضافة الإنتاج.
