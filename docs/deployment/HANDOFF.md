**وجهة إشعارات التواصل التي حددها المالك:** `moh.albadry89@gmail.com`. البريد الرسمي المعروض للزوار يبقى `info@ard-alyarmwk.com`. عنوان المرسل SMTP يجب أن يكون صندوقاً مصرحاً لدى مزود البريد، ولا يلزم أن يطابق وجهة الاستقبال.

## قبل فتح الموقع للجمهور

- مراجعة الشركة للنسختين: المقارنة كاملة في `docs/bilingual-review.html`. المراجعة التحريرية أُنجزت، واعتماد الشركة للإنكليزي ما زال مطلوباً. آلية الاعتماد موضحة في `docs/TRANSLATION-REVIEW.md`.
- تأكيد بيانات الاتصال وحقوق الصور المرجعية ومدة الاحتفاظ بالرسائل، وفق `docs/LAUNCH-CHECKLIST.md`.
- تجهيز نطاق HTTPS وPHP وMySQL وSMTP. استُخدم محلياً PHP 8.5.7 وMySQL 9.7.1؛ الكود يستهدف PHP 8.2+ وMySQL 8.0+، ولم تُختبر الإصدارات الدنيا أو MariaDB هنا. يلزم `pdo_mysql, mbstring, fileinfo, gd` مع WebP وPNG، و`openssl, zip, session, json`.

## رفع الملفات وإعداد الخادم

1. فك الأرشيف **خارج المجلد المنشور**، مثلاً `/home/ACCOUNT/ard-alyarmwk/`. اجعل Document Root للدومين يشير إلى `/home/ACCOUNT/ard-alyarmwk/public/` فقط. لا تضع `app`, `config`, `database`, `docs`, `storage` أو `vendor` داخل جذر الويب. إذا كانت الاستضافة تمنع تغيير Document Root، يهيئ مسؤولها ربطاً آمناً إلى `public/`؛ لا تنقل الملفات كلها إلى `public_html`.
2. على Apache فعّل rewrite وقراءة `public/.htaccess`؛ على Nginx عدّل `docs/deployment/nginx.conf` للمسار والنطاق وشهادة TLS وPHP-FPM. تُحجب ملفات الفيديو والقراءة المباشرة في `/assets/video/` و`/assets/profile/` وتُقدم عبر `/media/`.
3. استخدم PHP بحدود `upload_max_filesize=40M`, `post_max_size=42M`, `memory_limit=256M` على الأقل، وطبّق حدود خادم متوافقة. ملف الأصل 107 MB مرفق جاهز بالخادم؛ حد الرفع الإداري 40 MiB. النسخة المستخدمة للقراءة 4.2 MB والفيديو أقل من 1 MB.
4. أنشئ قاعدة MySQL بترميز utf8mb4 ومستخدم خاص. انسخ `config/production.example.php` إلى `config/local.php`، ثم أكمل النطاق `base_url` وDSN ومستخدم القاعدة وكلمة المرور. قالب الإنتاج يتضمن وجهة إشعارات المالك دون أي أسرار. أنشئ `app_key` جديداً بالأمر التالي وضعه في الإعداد:

```sh
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

5. احتفظ بـ `env=production`, `session_secure=true`, `require_approved=true`. امنح PHP القراءة على الكود والإعداد الخاص، والكتابة على `storage/` فقط؛ ملف الإعداد 600 أو صلاحيات ملائمة لمالك PHP. لا تستخدم 777. أنشئ مجلدات `storage/uploads`, `storage/logs`, `storage/mail` إن لم توجد.

## تثبيت القاعدة والمسؤول

من مجلد المشروع، عبر Terminal/SSH أو سطر الأوامر الذي توفره الاستضافة:

```sh
composer install --no-dev --prefer-dist
php bin/migrate.php
php bin/seed.php
php bin/install-profile-web.php
php bin/create-admin.php --email=ADMIN_EMAIL
```

اعتمادات PHP المجهزة موجودة أيضاً في `vendor/`؛ لا يحتاج التشغيل Node أو Python. لا يُستخدم حساب المسؤول المحلي على الإنتاج. تطلب أداة إنشاء المسؤول كلمة مرور مخفية؛ لا تكتبها ضمن الأمر ولا داخل الملفات العامة. رابط الإدارة بعد الرفع: `https://YOUR-DOMAIN/admin`.

تُثبت القطاعات الثمانية والنصوص والغلاف وPDF والفيديو تلقائياً. `seed.php` يحافظ على المحتوى الموجود ولا يعيد كتابته؛ لا تعاود البذر لتحديث قاعدة فيها تعديلات. اسحب صلاحيات إنشاء/تعديل المخطط من مستخدم التشغيل بعد التثبيت، وأبقِ SELECT/INSERT/UPDATE/DELETE. إذا لم تتوفر Terminal، ينفذ مسؤول الاستضافة هذه الأوامر؛ لا توجد صفحة تثبيت ويب عامة.

## البريد والمهام الدورية

اضبط `mail_transport=smtp` وحقول `smtp`: host، port، encryption=`tls` للمنفذ 587 أو `smtps` للمنفذ 465، username، password، from. حقل `to` مضبوط على بريد المالك أعلاه. أكمل SPF/DKIM/DMARC لدى مزود البريد حسب إعداداته.

أضف مهمة دورية مع مسار PHP الفعلي ومسار المشروع، مثلاً:

```cron
* * * * * cd /home/ACCOUNT/ard-alyarmwk && /usr/bin/php bin/mail-worker.php >> storage/logs/mail-worker.log 2>&1
```

تُحفظ رسائل التواصل قبل تأكيد الاستلام؛ نجاح الحفظ مستقل عن البريد. الإشعار يرسل الرقم المرجعي ورابط الإدارة فقط. بعد تجهيز SMTP، أرسل رسالة اختبار من الموقع النهائي، وافحص وجودها في اللوحة ثم وصول الإشعار إلى البريد المحدد وحالته `sent`. الإشعار الفاشل يعاد جدولته من اللوحة بعد إصلاح السبب. لم يُرسل بريد خارجي أثناء تطوير هذه الحزمة.

جهّز النسخ الاحتياطي والاحتفاظ وتدوير السجلات وفق `docs/BACKUP-RESTORE.md`. الأمر `php bin/backup.php` جاهز؛ لا يتضمن المصدر أي أرشيف بيانات خاصة. اختبر الاستعادة على قاعدة فارغة منفصلة قبل الاعتماد على النسخ.

## فحص التسليم النهائي

```sh
php bin/check-launch.php
```

يعيد رمز خروج 1 عند نقص الإعداد أو اعتماد المحتوى. لا يرسل بريدًا ولا يثبت صلاحية DNS/TLS؛ تلك اختبارات على الاستضافة. لا تعطّل شرط الاعتماد لتمرير الفحص. اختبر بعد اكتمال مراجعة الشركة:

- `/ar/`, `/en/`، تبديل اللغة مع الحفاظ على الصفحة، القطاعات الثمانية، PDF الخفيف والأصل، و404.
- التشغيل التلقائي بعد نهاية الفيديو، توقفه بزر الإيقاف، وعرض الهاتف.
- HTTPS وقفل الوصول إلى ملفات الإعداد والمجلدات الداخلية ومسارات الفيديو المباشرة. الطلب الجزئي `/media/{id}` يعيد 206.
- الدخول إلى `/admin` و`/admin/sliders`، تعديل سلايدر صفحة بلغة واحدة ومعاينته واستعادة الافتراضي، ثم تعديل محتوى تجريبي قابل للتراجع، حفظ رسالة التواصل وتسليم إشعارها، وجدولة النسخ.
- sitemap وcanonical وhreflang تحمل النطاق الصحيح. افحص من أجهزة فعلية قبل فتح الفهرسة/الإتاحة العامة.

تقارير الاختبارات المحلية في `docs/TEST-REPORT.md` و`tests/*-results.json`. اختُبر Chrome وWebKit محلياً؛ هذا لا يغني عن فحص خادم الاستضافة وTLS وSMTP والأجهزة الفعلية. احتفظ بنسخة رجوع قبل أي تحديث لاحق.

## تحديث النمط النهاري والليلي

ملفات النمط وأزراره جاهزة ضمن هذه الحزمة، ولا تحتاج ترحيل قاعدة بيانات. عند تحديث قاعدة موجودة شغّل `php bin/sync-theme-privacy.php` لإضافة بيان حفظ التفضيل إلى سياسة الخصوصية باللغتين؛ التثبيت الجديد يتضمنه. لم تتغير حالات اعتماد الشركة. اختبر زر الشمس/القمر وتذكر الاختيار في المتصفح بعد رفع الملفات. راجع `docs/THEMES.md`.
